## Overview

ESLint React provides direct equivalents for the core rules in `eslint-plugin-react-hooks`, including both the classic hooks linting rules (`exhaustive-deps`, `rules-of-hooks`) and many of the newer React Compiler diagnostic rules introduced in the latest versions of the plugin.

Rules specific to the React Compiler runtime (such as `config`, `gating`, `incompatible-library`, and `preserve-manual-memoization`) do not have equivalents in ESLint React, as they validate compiler-specific configuration and behavior.

- 🔧 **Fully supported** - Rule is supported, and has an auto-fix
- 🟢 **Mostly supported** - Rule is supported but doesn't have an auto-fix
- 🟡 **Partial support** - Similar but not identical functionality
- 🔴 **Not supported** - No equivalent rule
- 🧪 **Experimental** - Rule is supported but marked as experimental

### ESLint React Column

- Rule names link to ESLint React documentation
- Multiple rules separated by `+` indicate that together they provide equivalent functionality
- Rules marked 🧪 are experimental and their behavior may change in future releases
- Rules marked 🔴 are React Compiler-specific and have no equivalent in ESLint React

### Notes

- This table covers the documented rules of `eslint-plugin-react-hooks`, i.e. the ones listed on [react.dev](https://react.dev/reference/eslint-plugin-react-hooks) and enabled by its `recommended` preset. The upstream package additionally ships `void-use-memo` (enabled only in its `recommended-latest` preset; partially covered by [`use-memo`](/docs/rules/use-memo)), a deprecated `component-hook-factories` alias of `static-components`, and several off-by-default internal diagnostic rules.
- The 🔧 auto-fix of `exhaustive-deps` is gated behind the `enableDangerousAutofixThisMayCauseInfiniteLoops` option; by default the rule provides editor suggestions instead. See the [rule documentation](/docs/rules/exhaustive-deps) for details.
- Rules marked 🟡 have verified behavioral divergences from their upstream counterparts, tracked in each rule's `*.spec.diff.md` comparison report in the repository.

## Migration Preset

ESLint React provides a preset to disable conflicting rules from `eslint-plugin-react-hooks`:

- `disable-conflict-eslint-plugin-react-hooks` - Disables all rules from `eslint-plugin-react-hooks` that have equivalents in ESLint React (e.g., `react-hooks/exhaustive-deps`, `react-hooks/rules-of-hooks`, etc.)

This preset is useful when migrating from `eslint-plugin-react-hooks` to ESLint React, as it prevents rule conflicts while you transition your configuration.
